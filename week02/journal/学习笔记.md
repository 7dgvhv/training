# AI 使用与个人贡献说明

## 一、项目背景与我的角色

本次宿舍报修管理系统（第二周）要求将第一周的控制台程序升级为 Spring Boot + Vue 的 Web 应用，增加图片上传、JWT 鉴权、前后端分离等功能。我在项目中承担了**核心开发与调试**的工作，AI 主要作为辅助工具提供代码模板和思路参考，但关键的技术选型、代码迁移、功能调试、问题解决均由我完成。

## 二、我自己完成的核心工作

### 1. 第一周代码的迁移
- **手动迁移实体类与 Mapper**：将第一周项目中的 `User`、`RepairOrder` 实体类复制到新项目，并添加 MyBatis-Plus 注解（`@TableName`、`@TableId`、`@TableField`），保证数据库表映射正确。  
- **改造 Service 层**：第一周通过 `DbUtils` 手动管理 SqlSession，我将其全部替换为 MyBatis-Plus 的 `BaseMapper` 方法，并利用 `@Autowired` 注入 Mapper，完全融入 Spring 容器。  
- **移除冗余代码**：彻底删除了第一周的控制台交互类 `ConsoleUI` 和 `Main`，确保项目无遗留逻辑。

### 2. 后端核心功能的自实现
- **JWT 鉴权**：独立编写了 `JwtUtil` 工具类，实现 token 的生成、解析、验证，并在 `JwtInterceptor` 中完成请求拦截和用户信息注入，确保所有 `/api/**` 接口（除登录注册外）都需要 token。  
- **文件上传**：设计 `FileUploadUtil`，处理图片保存、目录创建、文件名生成，并配置静态资源映射，使上传的图片可通过 URL 直接访问。  
- **统一异常处理**：创建 `BusinessException` 和 `GlobalExceptionHandler`，统一捕获业务异常和系统异常，返回规范的 `Result` 对象，避免后端直接输出错误堆栈。  
- **管理员接口补全**：AI 最初未提供管理员修改密码和查看基本信息接口，我自行在 `AdminController` 中添加了这两个方法，并与 Service 层对接，保证管理员功能完整。

### 3. 前端问题的深度调试与修复
虽然前端基础代码由 AI 生成，但我投入了大量精力解决实际运行中出现的各类问题，具体包括：

- **函数命名冲突**：`StudentHome.vue` 中同时导入了 `bindDorm` 等 API 函数并定义了同名的本地方法，导致编译报错。我通过导入时使用别名（如 `import { bindDorm as apiBindDorm }`），并修改所有调用处，彻底解决了重复声明问题。  
- **管理员详情查看失败**：最初点击详情时控制台报错 `Cannot read properties of null (reading 'status')`。我通过以下步骤定位并解决：  
  - 在 `viewDetail` 中添加 `console.log` 打印响应内容，发现后端返回的数据结构与前端预期不一致（有时直接返回实体，有时返回 `Result` 包装）。  
  - 修改前端代码，增加自适应解析逻辑：先判断 `res.code` 是否存在，若存在则取 `res.data`，否则直接将 `res` 视为数据实体。  
  - 同时在后端 `AdminController.getOrderDetail` 中增加对单号不存在的处理，返回明确的 404 错误码。  
- **学生端创建报修单无法入库**：AI 生成的后端接收参数使用 `@RequestParam` 导致无法同时接收 JSON 和图片。我重新设计了接口：  
  - 后端改用 `@RequestPart("order") RepairOrderRequest orderReq` 和 `@RequestPart(value = "image", required = false) MultipartFile image`。  
  - 前端使用 `FormData`，将 JSON 转为 Blob 后追加，图片直接追加。修改后创建功能正常。  
- **新创建的报修单不显示**：我分析后发现前端列表没有自动刷新，于是在 `createOrder` 成功后手动调用 `loadOrders()`，确保列表即时更新。  
- **第一周旧数据与新增数据兼容**：旧数据没有 `image_url` 字段，我在前端判断 `currentOrder.imageUrl` 是否存在再显示图片，避免报错。
- **状态更新和订单取消失败**：前端传的参数和后端接收使用的不一致，经常是前端传的是订单后端用单号来比对，结果总是找不到订单。修改前后端使其保持一致。

### 4. 整体联调与部署
- 配置跨域：在 `CorsConfig` 中精确设置前端地址 `http://localhost:5173`，并允许携带凭证，保证前后端正常通信。  
- 测试所有接口：使用 Postman 逐一验证登录、注册、创建报修单（含图片）、查询列表、更新状态、删除等接口，确保后端稳定。  
- 环境变量管理：将数据库密码、JWT 密钥等敏感信息放在 `application.yml` 中，未在代码中硬编码。

## 三、AI 的辅助角色与我的学习

AI 在以下方面提供了帮助：
- 生成了 Spring Boot 项目的初始 `pom.xml` 和 `application.yml` 模板，节省了配置时间。  
- 提供了 Vue 3 的 axios 拦截器、路由守卫等基础代码框架。  
- 在遇到报错时，AI 能快速给出排查方向和常见解决方案，加速问题定位。

但所有代码的修改、业务逻辑的完善、调试过程的推进，都由我完成。例如，AI 最初给出的 `AdminPanel.vue` 中存在状态更新按钮缺失的问题，我自行补充了弹窗内的下拉选择和更新逻辑；AI 对前端命名冲突的解决方案不完整，我通过别名彻底修复。

## 四、遇到的挑战与解决思路

| 挑战                                     | 我的解决思路                                                 |
| ---------------------------------------- | ------------------------------------------------------------ |
| **第一周代码与 Spring Boot 框架不兼容**  | 逐步删除手动管理 SqlSession 的代码，改用 MyBatis-Plus 的注入方式，保证事务自动管理。 |
| **JWT 拦截器导致静态资源被拦截**         | 在 `WebConfig` 的 `addInterceptors` 中明确排除 `/uploads/**` 路径，并配置资源映射。 |
| **图片上传后返回的相对路径前端无法访问** | 在后端 `FileUploadUtil` 中直接返回可访问的完整 URL（如 `/uploads/xxx.jpg`），前端直接使用该路径拼接 baseURL。 |
| **管理员更新状态后列表未刷新**           | 在 `updateStatus` 中调用 `loadOrders()` 并关闭弹窗，确保数据同步。 |
| **前端路由守卫导致刷新页面后 404**       | 修改路由模式为 `createWebHistory()`，并确保后端所有路径都返回 index.html（开发环境由 Vite 处理）。 |

## 五、总结与成长

通过本次项目，我不仅将第一周的控制台应用升级为完整的 Web 系统，更深入理解了 Spring Boot 的自动配置、MyBatis-Plus 的便捷操作、JWT 鉴权的实际应用以及前后端分离的开发模式。AI 虽然提供了基础代码，但**真正让项目跑起来、解决所有运行问题的，是我自己的代码能力和调试经验**。遇到问题时，我学会了应该先分析日志、定位原因，再动手修改，而不是盲目听从ai乱改代码，这种独立分析问题、解决问题的能力是我在这一周中最大的收获。

今后我会继续保持这种“借助工具但不依赖工具”的学习态度，不断夯实基础，提升开发能力。
