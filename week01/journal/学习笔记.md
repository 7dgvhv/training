# 宿舍报修管理系统学习笔记（第一周）

---

## 一、Maven 项目创建与依赖管理

### 1.1 从零搭建 Maven 项目
- **项目结构**：理解了 Maven 约定的目录布局（`src/main/java`、`src/main/resources`、`pom.xml`），使项目结构清晰，便于团队协作和跨 IDE 迁移。
- **依赖管理**：通过在 `pom.xml` 中声明依赖，Maven 自动从中央仓库下载所需 JAR 包，彻底告别手动导入 lib 的繁琐。
- **生命周期**：了解了 `compile`、`package`、`install` 等命令的作用，为后续持续集成打下基础。

### 1.2 关键依赖
- `mysql-connector-java`：MySQL 驱动
- `mybatis-plus`：MyBatis-Plus 框架（含 MyBatis）
- `jbcrypt`：密码哈希工具

## 二、MySQL 数据库设计与基础 SQL

### 2.1 表设计
- 学会了根据业务需求设计表结构，包括字段类型、主键、外键、索引等。
- 使用 `DATETIME` 记录创建和更新时间，并利用 `ON UPDATE CURRENT_TIMESTAMP` 自动更新 `updated_at`。

### 2.2 SQL 语句
- 编写了建表 SQL，熟悉了 `CREATE TABLE`、`FOREIGN KEY` 等语法。
- 在代码中虽然未手写 SQL，但通过 MyBatis-Plus 的底层实现加深了对 `SELECT`、`INSERT`、`UPDATE`、`DELETE` 的理解。

### 2.3 数据完整性
- 使用唯一约束（`UNIQUE`）保证账号和报修单号不重复。
- 外键约束维护用户与报修单的关联一致性。

## 三、MyBatis-Plus 框架操作数据库

### 3.1 基础配置
- 使用 `MybatisSqlSessionFactoryBuilder` 结合自定义 `MybatisConfiguration` 初始化 `SqlSessionFactory`，实现无 XML 配置的 MyBatis-Plus 集成。

### 3.2 Mapper 层
- 只需让 Mapper 接口继承 `BaseMapper<T>`，即可获得完整的 CRUD 方法，无需编写任何 SQL 映射文件。

### 3.3 核心 API 使用
- **插入**：`mapper.insert(entity)`
- **删除**：`mapper.deleteById(id)`
- **更新**：`mapper.updateById(entity)`
- **查询**：
  - 按主键：`mapper.selectById(id)`
  - 条件查询：`LambdaQueryWrapper<T>` 配合 `eq`、`like`、`orderByDesc` 等构造类型安全的查询条件。
  - 查询列表：`mapper.selectList(wrapper)`
  - 查询数量：`mapper.selectCount(wrapper)`

### 3.4 事务管理
- 通过 `SqlSession` 的 `openSession(true)` 开启自动提交，简化了事务处理。若需手动控制，可调整为 `false` 并显式调用 `commit()`。

## 四、控制台交互与用户输入处理

### 4.1 菜单驱动的循环结构
- 使用 `while(true)` 和 `switch-case` 实现登录前后的不同菜单分支，并利用 `currentUser` 状态控制流程。

### 4.2 密码输入隐藏
- 学习了 `System.console().readPassword()` 方法，在命令行环境下实现密码隐藏。
- 处理了 IDE 中 `console` 为 `null` 的情况，采用降级方案（明文提示），保证程序在任何环境都能运行。

### 4.3 输入校验与异常处理
- 对用户输入的学号/工号进行正则校验，确保格式正确。
- 使用 `try-catch` 处理数字转换异常，避免程序崩溃。

## 五、代码分层设计

### 5.1 三层架构
- **控制层（console）**：负责界面交互，不包含业务逻辑。
- **服务层（service）**：处理业务逻辑，调用 Mapper 层接口。
- **持久层（mapper）**：数据访问，继承 MyBatis-Plus 的 BaseMapper。

### 5.2 接口与实现分离
- 服务层定义接口（`UserService`、`RepairOrderService`），实现类放在 `impl` 包中，便于后续扩展（如切换不同数据库实现）。

### 5.3 常量管理
- 使用接口或类集中管理角色常量（`RoleConst`）和状态常量（`OrderStatusConst`），避免硬编码，提高可维护性。

### 5.4 工具类封装
- `DbUtils`：封装数据库会话管理，提供统一的 `execute` 方法，避免重复的会话创建与释放代码。
- `PasswordUtils`：集中处理加密逻辑。
- `InputValidator`：校验账号格式。
